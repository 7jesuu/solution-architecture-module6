## Компоненты и их роли

| Компонент | Роль в целевой архитектуре |
|-----------|---------------------------|
| **Operational Systems** (Core, CRM, Cards, Loans) | Источники правды для финансовых и операционных сущностей. Остаются OLTP. |
| **MDM (Customer + Reference Hub)** | Единственный источник золотых записей клиентов, организаций и критичных справочников. |
| **Integration Layer (ESB + API Gateway)** | Синхронный обмен, маршрутизация, трансформация, политика доступа. |
| **Kafka** | Событийная шина: CDC-потоки, доменные события, near real-time интеграция. |
| **DWH** | Регламентированная и управленческая отчётность, согласованные витрины, история изменений. |
| **Data Lakehouse** (Apache Iceberg + Trino) | Большие исторические данные, события, сырые выгрузки, ad-hoc аналитика, ML-фичи. |
| **BI** | Дашборды, self-service, регламентированные отчёты. |
| **Airflow** | Оркестрация batch- и hybrid-пайплайнов. |
| **DataHub** | Каталог данных, lineage, владельцы, качество, discovery. |
| **Object Storage** | Документы, архивы, сырые файлы, landing zone Lakehouse. |

## Принципы целевой архитектуры

1. **Разделение OLTP и OLAP** — аналитика никогда не читает напрямую из Core/CRM.
2. **MDM** — единственная точка изменения критичных клиентских и справочных данных.
3. **Event-driven** там, где нужна актуальность (клиент, статусы, ключевые события).
4. **Batch + CDC** для тяжёлых финансовых и исторических данных.
5. **Единый каталог и lineage** — обязательное требование регулятора и Data Office.
6. **Постепенное отключение** legacy-систем RetailBank после полной миграции данных и потребителей.
