# 1. Ключевые бизнес-сущности

Ниже приведён итоговый набор из **12 ключевых сущностей**.  
Стартовый список из кейса расширен сущностями, без которых невозможно построить единый клиентский профиль, корректную отчётность и управляемые интеграции.

| № | Сущность | Почему включена / исключена |
|---|----------|-----------------------------|
| 1 | Клиент (Party / Customer) | Ядро единой модели. Без неё невозможно слияние. |
| 2 | Договор (Agreement / Contract) | Связывает клиента с продуктами и счетами. |
| 3 | Продукт (Product) | Необходим для унификации продуктовой линейки. |
| 4 | Счёт (Account) | Основная операционная сущность. |
| 5 | Карта (Card) | Отдельный жизненный цикл, статусы и тарифы сильно различаются. |
| 6 | Кредит / Заём (Loan) | Высокая регуляторная и кредитная критичность. |
| 7 | Операзакция / Операция (Transaction) | Основа финансовой отчётности и антифрода. |
| 8 | Платёж (Payment) | Часто отделяется от транзакции (инициирование vs исполнение). |
| 9 | Обращение клиента (Customer Interaction / Case) | Контактный центр + единый 360°-профиль. |
| 10 | Справочник (Reference Data) | Тарифы, отделения, сегменты, статусы — источник рассинхронизации. |
| 11 | Организация / Контрагент (Counterparty) | Нужна для МСБ и юридических лиц. |
| 12 | Событие / Документ (Event / Document) | Для lineage, аудита, Data Lake и регуляторных требований. |

---

## Детальное описание сущностей

### 1. Клиент (Customer / Party)
- **Описание**: Физическое или юридическое лицо, имеющее отношения с банком.
- **Основные атрибуты**:
  - `customer_id` (единый)
  - `source_system_id` + `source_customer_id` (для lineage)
  - ФИО / Наименование
  - ИНН, ОГРН, паспорт / реквизиты
  - Дата рождения / дата регистрации
  - Контакты (телефон, email, адрес)
  - Сегмент, статус, дата открытия отношений
  - `golden_record_flag`, `match_confidence`
- **Связи**: 1→N Договор, 1→N Счёт, 1→N Карта, 1→N Кредит, 1→N Обращение, N→N Организация (роли).
- **Системы-источники**: FinUnion CRM, RetailBank CRM, Core Banking обеих сторон, Карты, Loans.
- **Критерий включения**: Без единого клиента невозможно достижение бизнес-целей.
- **Проблемы качества**:
  - Дубли между банками и внутри систем
  - Разные идентификаторы
  - Разные форматы ФИО, адресов, телефонов
  - Устаревшие контакты
  - Отсутствие единого правила «кто является клиентом»

### 2. Договор (Agreement / Contract)
- **Описание**: Юридическое соглашение между банком и клиентом о предоставлении продукта.
- **Основные атрибуты**: `agreement_id`, `customer_id`, `product_id`, дата начала/окончания, статус, условия, валюта, канал заключения.
- **Связи**: N→1 Клиент, N→1 Продукт, 1→N Счёт / Карта / Кредит.
- **Источники**: Core Banking (FU/RB), CRM, Loans.
- **Проблемы**: Разные модели договоров, отсутствие единого статуса, разные справочники каналов.

### 3. Продукт (Product)
- **Описание**: Банковский продукт (счёт, вклад, кредит, карта и т.д.).
- **Атрибуты**: `product_id`, код, наименование, тип, линейка, тарифный план, статус, дата вывода/вывода из продажи.
- **Связи**: 1→N Договор, N→1 Справочник тарифов.
- **Источники**: Core, CRM, Cards, Loans.
- **Проблемы**: Разные коды продуктов, разные названия одних и тех же продуктов, отсутствие единого каталога.

### 4. Счёт (Account)
- **Описание**: Банковский счёт (расчётный, текущий, вклад и т.д.).
- **Атрибуты**: `account_id`, `customer_id`, `agreement_id`, номер счёта, валюта, баланс, статус, дата открытия/закрытия, тип счёта.
- **Связи**: N→1 Клиент, N→1 Договор, 1→N Транзакция, 1→N Карта (опционально).
- **Источники**: FinUnion Core, RetailBank Core.
- **Проблемы**: Разные модели счетов, разные статусы, отсутствие единого формата номера.

### 5. Карта (Card)
- **Описание**: Платёжная карта.
- **Атрибуты**: `card_id`, `account_id`, `customer_id`, маскированный номер, тип карты, статус, дата выпуска/истечения, тариф, лимиты.
- **Связи**: N→1 Счёт, N→1 Клиент, 1→N Операция по карте.
- **Источники**: Карты FinUnion, Карты RetailBank.
- **Проблемы**: Разные статусы карт, разные тарифы, разные события жизненного цикла.

### 6. Кредит / Заём (Loan)
- **Описание**: Кредитный продукт / договор займа.
- **Атрибуты**: `loan_id`, `customer_id`, `agreement_id`, сумма, ставка, срок, остаток долга, статус, график платежей, обеспечение.
- **Связи**: N→1 Клиент, N→1 Договор, 1→N Транзакция (платежи по кредиту).
- **Источники**: FU Заимствования, Заимствования RetailBank (Loans).
- **Проблемы**: Разные правила продуктов, разные модели графиков, разные статусы.

### 7. Транзакция / Операция (Transaction)
- **Описание**: Финансовая операция по счёту/карте/кредиту.
- **Атрибуты**: `transaction_id`, `account_id` / `card_id` / `loan_id`, сумма, валюта, дата/время, тип операции, направление, статус, канал, контрагент.
- **Связи**: N→1 Счёт / Карта / Кредит.
- **Источники**: Core Banking, Cards, Loans, платёжные системы.
- **Проблемы**: Разные коды операций, разная детализация, разное время фиксации.

### 8. Платёж (Payment)
- **Описание**: Инициирование и исполнение платежа (может отличаться от транзакции).
- **Атрибуты**: `payment_id`, инициатор, получатель, сумма, назначение, статус жизненного цикла, канал.
- **Связи**: N→1 Клиент, N→1 Счёт, может порождать Транзакцию.
- **Источники**: Core, платёжные шлюзы, CRM (заявки).
- **Проблемы**: Разделение «платёж» vs «проводка» не унифицировано.

### 9. Обращение клиента (Customer Interaction / Case)
- **Описание**: Обращение, претензия, консультация, заявка.
- **Атрибуты**: `case_id`, `customer_id`, канал, тема, статус, дата создания/закрытия, сотрудник, приоритет, результат.
- **Связи**: N→1 Клиент, может ссылаться на Договор / Счёт / Карту / Кредит.
- **Источники**: FinUnion CRM, RetailBank CRM, контактный центр.
- **Проблемы**: Разные классификации тем, отсутствие единого ID клиента, потеря истории при переходе.

### 10. Справочник (Reference Data)
- **Описание**: Нормативно-справочная информация (тарифы, отделения, сегменты, статусы, коды операций, валюты и т.д.).
- **Атрибуты**: зависят от типа справочника (`ref_type`, `code`, `name`, `valid_from`, `valid_to`, `source_system`).
- **Связи**: используется почти всеми сущностями.
- **Источники**: все системы.
- **Проблемы**: Полная рассинхронизация, отсутствие единого владельца, разные коды одних и тех же значений.

### 11. Организация / Контрагент (Counterparty / Organization)
- **Описание**: Юридическое лицо (клиент МСБ или контрагент по платежу).
- **Атрибуты**: `org_id`, наименование, ИНН, ОГРН, адрес, статус, роли (клиент / контрагент / бенефициар).
- **Связи**: N→N Клиент (через роли), 1→N Договор / Счёт.
- **Источники**: Core, CRM, платёжные системы.
- **Проблемы**: Дублирование с клиентами-юрлицами, разные реквизиты.

### 12. Событие / Документ (Event / Document)
- **Описание**: Бизнес-событие или документ (договор, заявление, выписка, скан, лог изменения).
- **Атрибуты**: `event_id` / `document_id`, тип, связанная сущность, дата, источник, ссылка на хранилище, hash, статус.
- **Связи**: N→1 почти любая сущность.
- **Источники**: все системы + файловые хранилища.
- **Проблемы**: Нет единого каталога, нет lineage, документы разрознены.
