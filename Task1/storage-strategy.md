| Группа данных | Рекомендуемый тип хранилища | Обоснование | Примечание по переходному периоду |
|---------------|-----------------------------|-------------|-----------------------------------|
| Операционные данные (счета, договоры, платежи, карты, кредиты в реальном времени) | **OLTP БД** (существующие Core Banking + CRM) | Высокая транзакционная нагрузка, ACID, низкая latency | Не трогаем в первые 3 месяца. Только read-реплики / CDC. |
| Золотые записи клиентов и критичные справочники | **MDM** | Единый golden record, match & merge, survivorship rules | Обязательный компонент уже к 3-му месяцу |
| Регламентированная и управленческая отчётность | **DWH** (классическое хранилище) | Структурированные витрины, история изменений, аудит | Временные витрины на 3 месяца → целевой DWH к 12 месяцам |
| Большие исторические, событийные, слабоструктурированные данные | **Data Lakehouse** | Хранение сырых событий, логов, документов + возможность SQL-аналитики | Целевая платформа. На 3 месяца — минимальный landing zone |
| Документы, сканы, выгрузки, архивы | **Объектное хранилище** (S3-совместимое) | Дешёвое хранение больших объёмов, версионирование, lifecycle | Уже частично есть. Нужно единое пространство имён и метаданные |
| Связи клиентов, контрагентов, бенефициаров, граф отношений | **Графовая БД** (опционально) | Сложные связи «клиент–контрагент–бенефициар», antifraud | Обоснована при развитии МСБ и антифрода. Не критично на 3 месяце |
| Поиск по обращениям, клиентам, документам | **Поисковый движок** (Elasticsearch / OpenSearch) | Полнотекстовый + фасетный поиск для КЦ и сотрудников | Желательно к 6–9 месяцу, не блокер для 3 месяцев |



## Принципы
1. **OLTP не нагружается аналитикой** — только CDC / реплики.
2. **MDM** — единственный источник правды для клиента и ключевых справочников.
3. **Lakehouse** принимает сырые данные (включая историю из RetailBank) и постепенно становится основной аналитической платформой.
4. **DWH** остаётся для жёстко регламентированной отчётности (регулятор + управленческая).
5. Все потоки должны иметь **lineage** и проходить через каталог данных.
