# 1. Образ целевого результата (через 12 месяцев)

| Вопрос | Что должно измениться |
|--------|-----------------------|
| **Какие системы остаются** | Target Core Banking (или эволюционировавший FU Core), единый CRM, Card Management, Loan System, **MDM Customer & Reference Hub**, Integration Layer (ESB + Kafka), **DWH**, **Data Lakehouse** (Iceberg + Trino), BI, Airflow, DataHub, Object Storage |
| **Какие системы выводятся из эксплуатации** | Point-to-point интеграции RetailBank, отдельные RB CRM / RB Core / RB Cards / RB Loans (после полной миграции данных и потребителей), разрозненные локальные витрины, прямые аналитические подключения к OLTP |
| **Какие данные мигрируются** | Клиенты и организации → MDM (golden records); справочники → MDM Reference; история счетов, транзакций, карт, кредитов → Lakehouse (+ витрины в DWH); обращения → единый Case/CRM; документы и архивы → Object Storage + метаданные в каталоге |
| **Какие потоки переключаются** | Все изменения клиента идут только через MDM; финансовая аналитика читает только из DWH/Lakehouse; регуляторная отчётность — только из DWH; события — через Kafka; справочники распространяются из MDM |
| **Критерии завершения перехода** | 1) 100% активных клиентов имеют единый `customer_id` и golden record в MDM<br>2) Управленческая и регуляторная отчётность строится из единых витрин без ручных сверок между банками<br>3) Нет критичных point-to-point потоков RB<br>4) Lineage и владельцы зарегистрированы в DataHub для всех критичных наборов данных<br>5) Dual-run завершён, legacy RB-системы переведены в read-only / отключены<br>6) SLA по ключевым витринам выполняются ≥ 99% дней в течение 1 месяца |
