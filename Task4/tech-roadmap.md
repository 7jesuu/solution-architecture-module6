# 5. Технологическая дорожная карта

Используется модель **Wardley / Thoughtworks-style**: Adopt / Trial / Assess / Hold.

| Зона | Технологии и подходы | Почему в этой зоне |
|------|----------------------|--------------------|
| **Adopt** (внедряем и делаем стандартом) | **MDM** (Customer + Reference Hub)<br>**Kafka** (+ CDC, напр. Debezium)<br>**Airflow**<br>**PostgreSQL DWH** (на переходный период и регламент)<br>**DataHub** (каталог, lineage, owners)<br>**dbt** + DQ-фреймворк<br>**Integration Layer** (ESB/API Gateway) | Уже необходимы для достижения целей 3-го и 12-го месяца. Дают быстрый контролируемый результат и являются фундаментом. |
| **Trial** (активно пилотируем) | **Apache Iceberg**<br>**Trino**<br>**Data Lakehouse** как платформа<br>**Spark / Flink** для тяжёлой обработки<br>**Domain Data Products** (как практика) | Ключевые компоненты целевой архитектуры. Нужны пилоты на реальных объёмах (карточная история, архивы RB), чтобы подтвердить эксплуатационную готовность до массового переноса. |
| **Assess** (изучаем, ещё не внедряем) | **Полноценный Data Mesh**<br>**Графовая БД** для связей клиентов/контрагентов<br>**Feature Store** для ML<br>**Обратная совместимость через data contracts** в более жёстком виде | Полезны в будущем, но требуют зрелости платформы и команд. На горизонте 12 месяцев не являются блокерами. |
| **Hold** (не используем / выводим) | **Point-to-point интеграции** RetailBank<br>**Прямой доступ аналитиков к OLTP**<br>**Локальные «таблички» и теневые витрины**<br>**Хранение критичных ПДн в незашифрованном виде в файловых выгрузках** | Создают риски, дублирование и тормозят миграцию. Подлежат замещению или запрету. |

## Краткая логика движения технологий

0–3 мес     Adopt: MDM, Kafka, Airflow, PostgreSQL DWH, DataHub
3–6 мес     Trial → частичный Adopt: Iceberg, Trino, Lakehouse Bronze/Silver
6–12 мес    Расширение Lakehouse Gold, data-продукты, сокращение legacy
12+ мес     Assess → возможный Trial: более зрелый Mesh, граф, feature store
