# 4. Пайплайны данных

## Основные пайплайны

| Пайплайн | Источник | Приёмник | Тип | Инструменты | Назначение |
|----------|----------|----------|-----|-------------|------------|
| **1. Клиентский (MDM)** | FU CRM, RB CRM | MDM Customer Hub | ETL / Streaming | Kafka, Airflow, match-engine | Построение golden record, единый customer_id |
| **2. Простой DWH (3 месяца)** | MDM, FU Core, RB Core (реплики/выгрузки) | PostgreSQL DWH | Batch ELT | Airflow, dbt, Python | Единая управленческая отчётность на 3-м месяце |
| **3. Финансовый CDC** | FU Core, RB Core, Cards, Loans | Lakehouse (Bronze → Silver) + DWH | CDC + ELT | Debezium, Kafka, Spark/Flink, dbt | Near real-time и исторические финансовые данные |
| **4. Справочники** | MDM Reference Data | DWH, Lakehouse, кэши потребителей | CDC / Broadcast | Kafka, Airflow | Централизованное распространение справочников |
| **5. Витрины BI** | DWH + Lakehouse Gold | BI-витрины | Batch | Airflow, dbt | Регламентированные и self-service витрины |

## Детализация простого пайплайна для 3 месяцев (PostgreSQL DWH)

**Название:** `daily_management_reporting_v1`

| Шаг | Описание | Инструмент |
|-----|----------|------------|
| 1 | Извлечение клиентов из MDM (golden) | Airflow + API/DB |
| 2 | Извлечение счетов, договоров, транзакций из реплик/выгрузок FU Core и RB Core | Airflow + SQL/Files |
| 3 | Нормализация и маппинг статусов/продуктов через справочники MDM | dbt |
| 4 | Построение fact- и dim-таблиц в PostgreSQL DWH | dbt |
| 5 | Расчёт витрин (клиенты, остатки, обороты, кредитный портфель) | dbt |
| 6 | Data Quality checks (полнота, сверка сумм, дубли) | dbt tests / Great Expectations |
| 7 | Публикация витрин для BI | Airflow |

**Частота:** ежедневно (к 07:00).  
**SLA:** данные за T-1 доступны к 07:00.

## Сценарии обработки больших исторических / событийных данных

### Сценарий A. История карточных операций двух банков

| Поле | Значение |
|------|----------|
| **Источник данных** | Выгрузки и CDC из FU Cards и RB Cards + архивные файлы RetailBank |
| **Характер данных** | Исторические + событийные, большой объём, полуструктурированные (разные форматы статусов) |
| **Целевое хранилище** | Data Lakehouse (Bronze → Silver → Gold) |
| **Способ обработки** | Первичная загрузка — Batch (исторические файлы). Далее — CDC/Streaming в Kafka → Bronze. Очистка и унификация статусов — Spark/dbt в Silver. Агрегаты для антифрода и отчётности — Gold |
| **Потребители** | Антифрод, риск-менеджмент, BI, регуляторная отчётность (через витрины) |

### Сценарий B. Архивные выгрузки и события клиентских каналов после слияния

| Поле | Значение |
|------|----------|
| **Источник данных** | Архивные выгрузки RetailBank (файлы), события мобильного/веб-канала, логи обращений |
| **Характер данных** | Архивные, событийные, слабоструктурированные |
| **Целевое хранилище** | Object Storage (сырьё) + Lakehouse Bronze/Silver |
| **Способ обработки** | Batch-загрузка архивов → Bronze. Streaming событий каналов через Kafka. Нормализация и привязка к customer_id (через MDM) → Silver. Витрины поведения клиента → Gold |
| **Потребители** | Маркетинг, Customer 360, КЦ, data science (ML-модели оттока и next-best-action) |
