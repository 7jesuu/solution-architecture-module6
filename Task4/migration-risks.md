# 4. Риски миграции

| Риск | Влияние | Вероятность | Митигация |
|------|---------|-------------|-----------|
| **Дубли и ложные объединения клиентов** | Ошибки в профиле, коммуникациях, кредитных решениях, претензии клиентов | Высокая | Жёсткие правила match + ручная верификация спорных случаев; «безопасный» режим (не объединять при низком confidence); аудит всех merge |
| **Рассинхрон остатков и транзакций при CDC** | Некорректная отчётность, регуляторный риск | Высокая | Dual-run сверки, reconciliation jobs, контрольные суммы по счетам и оборотам, запрет переключения отчётности до стабильных сверок |
| **Деградация клиентских сервисов при переключении** | Остановка обслуживания, репутационный ущерб | Средняя | Cutover в окна минимальной нагрузки, предварительные нагрузочные тесты, готовый фолбэк, мониторинг 24/7 |
| **Потеря истории обращений / документов** | Нарушение качества сервиса, претензии, регуляторные вопросы | Средняя | Предварительная миграция истории в Lakehouse/CRM с привязкой к `customer_id`, выборочная проверка, хранение исходных архивов |
| **Сопротивление бизнеса и обход MDM** | Появление новых «теневых» процессов и дублей | Высокая | Чёткий ownership, обучение, блокировка прямых изменений критичных атрибутов в CRM, KPI на использование golden record |
| **Нехватка компетенций по Lakehouse/Iceberg/Trino** | Срыв сроков, нестабильная платформа | Средняя | Обучение, пилоты на некритичных данных, привлечение внешней экспертизы на старте, чёткое разделение DWH (проще) и Lakehouse |
| **Срыв сроков из-за недооценки объёма данных RB** | Перенос cutover, рост стоимости | Средняя | Ранний data discovery с замерами объёмов, пилотные загрузки, буфер в плане (этапы 4–5) |
| **Регуляторные претензии к отчётности в переходный период** | Штрафы, предписания | Средняя | Dual-run старой и новой отчётности, документированный reconciliation, временные контрольные процедуры, согласованный с финдепом план |
| **Утечка ПДн при массовых выгрузках** | Нарушение 152-ФЗ, ИБ-инциденты | Низкая / Средняя | Шифрование, маскирование в non-prod, ограничение доступа, аудит выгрузок, работа только через Integration Layer |
| **Зависимость от legacy point-to-point RB** | Невозможность быстро отключить старое | Высокая | Приоритетное замещение критичных P2P-потоков на Integration Layer уже на этапах 2–4 |
