# 3. Классификация данных

| Сущность | Категория данных | Критичность | Влияние на ИБ / регуляторику | Средства защиты |
|----------|------------------|-------------|------------------------------|-----------------|
| **Клиент** | ПДн + банковская тайна | Критическая | Утечка = нарушение 152-ФЗ, 395-1-ФЗ, возможные штрафы и репутационный ущерб | Шифрование at-rest/in-transit, маскирование, токенизация, RBAC + ABAC, полный аудит доступа, DLP |
| **Договор** | Банковская тайна + коммерческая | Высокая | Содержит условия и персональные данные | Шифрование, RBAC, аудит изменений, версионирование |
| **Продукт** | Справочные / коммерческие | Средняя | Ошибки приводят к некорректным продажам и отчётности | Контроль изменений, версионирование, разграничение прав |
| **Счёт** | Банковская тайна + финансовые | Критическая | Прямое влияние на баланс и отчётность | Шифрование, строгий RBAC, аудит всех операций, мониторинг аномалий |
| **Карта** | ПДн + платёжные данные (PCI DSS) | Критическая | Утечка данных карт = PCI DSS + банковская тайна | Токенизация PAN, шифрование, PCI-compliant хранение, маскирование |
| **Кредит / Заём** | Банковская тайна + кредитная история | Критическая | Регуляторная отчётность, риск-менеджмент | Шифрование, RBAC, аудит, контроль доступа риск-подразделений |
| **Транзакция** | Банковская тайна + финансовые | Критическая | Основа регуляторной и управленческой отчётности, антифрод | Шифрование, иммутабельность после фиксации, аудит, мониторинг |
| **Платёж** | Банковская тайна | Высокая | Связан с движением денег | Шифрование, RBAC, аудит жизненного цикла |
| **Обращение** | ПДн + служебная | Высокая | Содержит персональные данные и историю взаимодействия | Маскирование в логах, RBAC, аудит доступа сотрудников КЦ |
| **Справочник** | Справочные | Средняя / Высокая (если тарифы) | Ошибки ломают расчёты и отчётность | Контроль изменений, dual-control, версионирование |
| **Организация** | ПДн юрлиц + банковская тайна | Высокая | Реквизиты и связи | Шифрование чувствительных полей, RBAC |
| **Событие / Документ** | Смешанная (ПДн + архив) | Высокая | Долгосрочное хранение, lineage, регуляторные требования | Шифрование, WORM/архивное хранение, контроль доступа, hash-проверка |

## Дополнительные правила
- Все поля, содержащие ПДн, должны иметь классификацию на уровне атрибута.
- В аналитических витринах ПДн по возможности маскируются или агрегируются.
- Доступ к критичным сущностям — только через контролируемые интерфейсы (API / MDM / DWH), прямой доступ к OLTP запрещён для аналитиков.
